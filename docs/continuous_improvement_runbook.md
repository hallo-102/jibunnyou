# JRA継続改善ループの運用

本番の重み・順位・買い目条件を維持したまま、既存のNAS朝処理へ固定保存、結果回顧、Shadow比較を追加する。候補の本番採用はユーザーが判断する。

## 配置と処理の所有者

| 処理 | 使用する既存機能・追加機能 |
|---|---|
| 開催判定・収集・オッズ・正式予想・従来配信 | 既存 `scripts.run_scheduler` / `scripts.run_daily_pipeline`。06:45 JST |
| 結果収集 | `etc_py/10_kekka_scraper_20260102.py`。固定出馬表のID一覧を引数で渡す |
| 特徴量・スコア・順位・買い目の生成 | 既存 `1_keibayosou_pipeline.py`。Shadowも同じ関数を使う |
| 3連複買い目抽出・精算 | 既存 `shadow_validation._bet_record` / `_settle_current_trifecta` |
| レースレベル・レーティング更新 | NAS既存 `maintenance/00_Export_To_Excel_4.py` と `scripts.update_masters.validate_race_levels` |
| 重み探索・符号制約・固定0・期間分割・採否 | 既存 `tokutyouryou_keisann`。CLI実行からbestを自動発行しない |
| 固定保存・条件別評価・再開・Drive保存 | 追加 `continuous_improvement` パッケージ |

NASの既存ルートは `/volume1/docker/keiba_yosou_2026_nas`、追加コードは `/volume1/docker/jra_continuous_improvement`。追加サービスは `deploy/continuous-improvement.compose.yaml` で定義し、既存サービスとは別のComposeプロジェクトで起動する。

## 開催日の動作

1. 既存の朝処理が06:45に開始する。追加サービスは1分おきにREADYを確認する。
2. READYとExcelのSHAを照合し、最初の発走前だけ入力・オッズ・予想Excel全体・実効重み・コード・マスタを `prospective/YYYYMMDD/pre/` へ固定保存する。対象日以降の結果マスタがあれば拒否する。
3. 同じ固定入力・マスタから、GitHub main由来のコードでShadowを計算する。正式予想へは書き込まない。発走までに計算が終わらなければ事前実績に算入しない。
4. 発走前保存とShadowをDriveへコピーし、読み戻し検査を行う。
5. 18:00以降、固定出馬表にあるレースだけの結果を収集する。取消・除外・競走中止・失格を区別し、全レース・全馬・必要払戻が揃うまで完了にしない。
6. 元の予想を保持し、結果反映Excel、全馬CSV、回顧JSON、回顧Markdown、モデル比較を別保存する。
7. 確定結果から新しいマスタを一時生成し、既存の検査に通った場合だけバックアップ後に更新する。次回の予想へ利用する。
8. Driveに結果を保存する。未完了日を永続状態から翌稼働日に継続する。

当日朝の既存処理がFAILEDで終了した場合、09:00までの範囲で15分間隔・最大3回、既存の再開オプションを使う。RUNNING中の既存処理は重複起動しない。夕方の失敗は30分後に再試行する。21:00以降は新しい夕方工程を開始せず、22:00以降は新規工程を開始しない。停止時刻22:30を跨いだ未完了工程は翌稼働時に再実行する。

## 保存物と評価の読み方

NAS保存先は既存ルートの `data/output/continuous_improvement/`。Driveは従来配信フォルダ内の `continuous_improvement/`。

| 保存物 | 意味 |
|---|---|
| `status.json` | 日付ごとの工程・失敗理由・再試行・最適化待機状態。Driveへ30分ごとに保存 |
| `prospective/YYYYMMDD/pre/manifest.json` | 固定時刻、入力・予想・コード・重み・マスタのSHA。既存ファイルは上書きしない |
| `prospective/YYYYMMDD/shadow_pre_実行アダプタSHA/` | Shadow予想、実効重み、ソース、コードSHA、完了時刻 |
| `post/実行コードID/結果SHA/` | 結果反映Excel、全馬CSV、`review.json`、`回顧.md` |
| `comparison.json` | 本番・Shadowの全体指標と、同じレース・馬集合に限定した比較 |
| `history.json` | 日付・実行コードID・role別の前向き成績。再照合を二重集計しない |
| `retrospective/` | 過去日の通し試験。前向き実績へ算入しない |
| `optimizer_status.json` | サンプル待ち、非開催日待ち、探索結果 |
| `optimization/` | 隔離した探索コード、マスタ、ログ、候補・採否履歴 |
| `active_shadow.json` | 検証ゲートを通過したShadow候補の隔離コピーを指す |

回顧には1位勝率・複勝率、TOP5の3着内馬捕捉、順位相関、単複回収率、固定買い目の3連複・馬連・ワイド回収率、人気・オッズ・場所・芝ダ・距離帯・クラス・馬場別集計、特徴量欠損・分布・相関・個別除外診断を含む。元の予想が対象外としたレースも、確定結果と除外対象IDを残す。

新馬・未勝利は主要評価から分ける。条件別35レース未満は母数不足と表示する。1日だけの結果で重みを確定しない。買い目の回収率は固定済み候補を100円単位で精算した値で、実際に購入したことの証明ではない。個別除外は加法スコア診断であり、買い目全体を本番と同じ手順で再生成した厳密な効果検証とは区別する。

取消・除外を含む馬番券は返還し、競走中止は返還しない。根拠は[JRAの馬券ルール](https://www.jra.go.jp/kouza/baken/)。開催全体の中止・不成立など、通常の結果表で確定できない日は未完了として残す。

## 探索と採用

直近のShadow世代に8開催日・300レース・固定3連複50対象レースの実績が集まるまで探索しない。既存の開催判定がNO_RACEとなった07:00〜12:00に隔離探索を開始し、最大3時間とする。現在は既存TOP5探索を100反復で再利用する。探索の目的関数自体を「利益最適化済み」と扱わず、候補の良否は次回以降の固定買い目回収率・収支・最大ドローダウンで評価する。

TRAIN・VALID・TESTは既存境界を維持し、2026-08-22以降の前向きデータを探索に戻さない。DL混合0では不要なDL学習を実行しない。DLが有効な設定では、対象日以前だけの学習が未検証のため探索を停止する。

検証ゲート・候補保存前後の実効SHAが合格した場合だけ、候補を隔離Shadowへ設定する。内部の本番互換ローダーのため隔離コピー内に `production_model.json` を置くが、NAS正式コードやGitHubのproduction設定は変更しない。隔離コピーのディレクトリは候補SHAごとに固定する。ユーザーが採用を判断するまでは本番へ昇格しない。

## 既存世代との関係

2026-10-24開始のローカル検証世代は履歴として保持する。GitHub mainの検証設定とは差があるため、新ループの成果物には `legacy_forward_generation: null` と実行コードIDを保存する。旧世代の成績を新ループへ移したり、過去日再計算を前向き成績へ算入したりしない。

## 停止・再開と確認

追加Composeプロジェクトだけを停止すれば、従来の朝処理は継続する。再起動時は固定保存をSHAで検証し、未完了工程を再開する。古いマスタは既存ルートの `backups/continuous_improvement/` に保持する。マスタ差し戻しはバックアップと更新監査のSHAを照合して行う。

ヘルスチェックはプロセスが状態を書けていることを確認する。業務成功は `status.json` の各工程と成果物を確認する。

Museの追加ジョブは作成しない。通常の継続処理はNASだけで実施し、改善候補をDriveから確認してCodexへ依頼する。Codex非対話実行は公式の `codex exec` で可能だが、NAS側CLI・自動実行用認証・利用料金や上限の確認は別途必要。認証を無断転送せず、LLM常時実行費用を追加しない。[公式の非対話実行と認証](https://learn.chatgpt.com/docs/non-interactive-mode#authenticate-in-automation)
