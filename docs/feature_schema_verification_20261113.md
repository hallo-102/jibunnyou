「4項目」は重みファイルSHA、実効重みSHA、グループ数、要素数である。`production_model.json`に特徴量定義の期待件数はなく、3,131要素の一致は定義102項目の全項目に重みがあることを意味しない。また重みキー101項目には値0の項目も含まれ、101項目すべてが非ゼロで寄与するという意味ではない。

## 差分の意味

頭数補正平均着順は、過去走ごとに `1 - (着順 - 1) / (頭数 - 1)` を0〜1に収めて平均する特徴量である。1着に近いほど1、最下位に近いほど0になる。

NAS本番101項目とmainの102項目は、この1項目を除き名前集合が完全一致した。本番側の不足・余剰キーは全31グループでゼロ。mainとNAS Shadowは全31グループでこの1項目だけ重みキーがなく、余剰キーはゼロだった。

`1_keibayosou_features.apply_weights()` は未設定キーを `weights.get(k, 0.0)` で0として扱う。WindowsとNAS Shadow双方の実際の採点関数に、この項目の値として-1000・0・1000を渡し、全31グループで寄与0・合計スコア不変を確認した。これは当該項目の寄与検証であり、別の計算修正やモデル変更まで順位不変だと保証するものではない。
