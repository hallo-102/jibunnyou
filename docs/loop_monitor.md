# JRA改善ループのWindowsモニター

NASの状態・朝処理ログを共有フォルダから読み取り、5秒ごとに表示を更新する専用アプリ。SSH・追加API・トークンは使わない。NASの状態記録自体は約1分ごとのため、画面の更新周期とNASの記録時刻を分けて表示する。

NASの `deploy/loop-monitor.compose.yaml` による独立観測が5秒ごとに `live/snapshot_日時_一意番号.json` を発行する。Windows SMBが同一パスの旧内容を返す問題を避け、アプリは最新の一意名ファイルを読む。36世代だけ保持する。観測側は業務領域を読み取り専用mountとし、観測出力以外には書き込まない。公開ポートは増やさない。観測が90秒以上更新されなければ前回値と明示する。

業務ループの更新時刻は長い子処理の間は進まないため、画面用のNAS観測時刻と区別する。実行中記録があっても、工程の完了までは成功と表示しない。

## 画面

- 今日の工程：監視、朝予想、発走前固定、Shadow、回顧、マスタ更新、Drive保存。
- 完了・進行中・待機・対象外・エラーを色と文字で表示する。
- NAS状態更新時刻とPC取得時刻、次の工程、直近ログ、元のJSONを表示する。
- 開始予定06:45から5分過ぎても記録がない場合、開始未確認として表示する。
- NASの状態更新が5分以上空いたら確認表示にする。長時間処理中の可能性もあるため、停止とは断定しない。
- 接続できない場合は前回取得値と明示する。読込中はGUIを止めず、同時通信は1本に制限する。
- 任意の日付の記録を参照でき、今日を表示中なら日付跨ぎで翌日へ追従する。

## 起動

配布フォルダの `JRALoopMonitor.exe` またはデスクトップの「JRA改善ループ」を開く。配布はonedir形式で、exeと同じフォルダの `_internal` を一緒に保持する。

初期接続先は `\\192.168.1.92\docker\keiba_yosou_2026_nas`。PCからこの共有へアクセスできる必要がある。Windowsに既存のNAS認証を登録している場合はそれを使う。アプリ内でパスワードは扱わない。接続先の変更はWindowsユーザー設定だけに保存する。

画面の「Google Driveを開く」は保存先をブラウザで表示するボタンであり、Driveから状態を取得する機能ではない。外出先ではNAS共有にアクセスできるVPN等が別途必要。

このアプリは予想処理の開始・停止、重み変更、購入を行わない。NASが22:30に停止する間は取得できない。PC上のアプリを閉じても、NASの継続ループには影響しない。

## ビルド

`scripts/build_loop_monitor.ps1` で既存の `jra_odds_strategy_monitor/.venv` 内のPySide6/PyInstallerを再利用する。`-Python` と `-Destination` で環境・出力先を指定できる。NAS側のコードや設定の変更は不要。

ビルド出力はOneDriveの属性干渉を避けて `%LOCALAPPDATA%/JRALoopMonitorBuild` に置く。既存OSMのspecと同じく、PATH上のPoppler用 `icuuc.dll` を同梱対象から外してWindows標準ICUを使う。Windows 11環境で起動確認する。
