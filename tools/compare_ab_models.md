# A〜D 時系列比較（Issue #32）

リポジトリの履歴を取得し、追跡済みファイルに変更のない作業ツリーから実行します。PR #31 のコミットを読み込むため、浅い clone では履歴の取得が必要です。依存は Python、pandas、NumPy、openpyxl、Git、GNU patch です。

```sh
python -m tools.compare_ab_models --config /path/to/run.json --output /path/to/empty-directory
PYTHONPATH=.:race_purchase_filter python -m pytest -q tests/test_ab_model_comparison.py tools/test_ab_comparison_evidence.py
```

## 実行設定

パスは設定ファイルのディレクトリを基準に解決します。GitHub の基準モデルを省略時の既定値にしています。NAS の基準モデルも比較する場合は `baselines` に追加します。両基準が異なる場合は各基準で別々に A〜D を集計し、C/D の学習済み重みは共有します。各基準モデルの設定は既存のモデルレジストリ形式で、ファイルと実効重みの SHA を照合します。A/B の学習期間が分かる場合は `training_period` で指定します。不明の場合はマニフェストに `unknown` を記録します。

```json
{
  "schema_version": 2,
  "snapshots": "snapshots.json",
  "results": "results.json",
  "periods": {
    "train": ["2025-06-14", "2026-06-30"],
    "validation": ["2026-07-01", "2026-10-23"],
    "forward": ["2026-10-24", null]
  },
  "baselines": {
    "github": {"model_config": "config/production_model.json"},
    "nas": {"model_root": "/path/to/nas-model-export", "model_config": "config/production_model.json"}
  },
  "unit_yen": 100,
  "box_size": 5,
  "top_payout_races": 3,
  "min_validation_settled_races": 30
}
```

期間は JST の両端を含み、`forward` の終端を `null` にすると上限を設けません。既存の場所別・場所×馬場別最適化とシードを使います。機能確認時は `optimizer_iterations` の `N_ITER_DEFAULT`、`N_ITER_PLACE`、`N_ITER_PLACE_SURFACE` に小さい値を指定できます。学習期間に開催され、学習締切までの利用可能性が証跡で確認できる結果を既存の TOP5 目的関数へ渡します。候補順位は検証締切までに利用可能と確認できた共通購入対象の利益額・回収率の順に付けます。標本数の閾値を満たさない場合は候補を選定しません。

## 発走前スナップショット

`snapshots.json` は1レース1要素の配列です。発走前に保存した元ファイルだけを使用し、取得時刻と SHA-256 を付けてください。例の SHA は実ファイルの値へ差し替えます。

```json
[
  {
    "race_id": "202605050101",
    "start_at": "2026-07-01T12:00:00+09:00",
    "input_evidence_grade": "A",
    "observed_at": "2026-07-01T11:55:00+09:00",
    "workbook": "archive/day.xlsx",
    "workbook_sha256": "<64桁のSHA-256>",
    "popularity_observed_at": "2026-07-01T11:54:00+09:00",
    "popularity": {"1": 2, "2": 1, "3": 3}
  }
]
```

- Excel の `今走レース情報` に `レースID`、`馬番`、`馬名`、`頭数` を収録します。開催日には発走時刻の JST 日付を用い、今走の最終オッズ・着順・払戻および既計算予想列を除去します。
- レースID名のシートは過去走に使用します。日付を確認でき、開催日より前の行だけを残します。付与時点を確認できる過去走指数を収録してください。
- 同じ発走前 Excel の `horses` シートに、照合キーと既計算特徴量があれば A/C で従来どおり補完します。B/D は再計算値を使用します。欠損の分離比較では、同じ保存済み特徴量を B に相当する計算の欠損セルだけに補完します。
- `race_levels`、`base_time`、`odds_csv` は任意のファイルパスです。指定時はそれぞれ同名の `_sha256`、`_observed_at` を添えます。予想取得時刻までの実体を本番ローダーで読み、両計算式と最適化で共用します。欠落件数はマニフェストに記録します。現在の特徴量経路で未使用のマスター列やオッズ列についても、入力の有無を記録します。
- 購入判定に使う人気は `popularity` に発走前順位を馬番別に指定します。同率で確定順位が不明な馬は省略できます。その場合は既存購入判定が保留となる場合があります。人気の取得時刻を省略した場合は `observed_at` を使います。
- DL の保存済み出力を使う場合は `dl` に馬番ごとの `probability` と `rank`、`dl_model_sha256`、`dl_model_training_end_at`、`dl_observed_at` を指定します。両経路で同じ発走前出力と本番ブレンド比を使います。欠落時は中立入力になります。このプログラムは NAS の現在のファイルから DL を再学習しません。
- SHA はファイル内容を固定します。取得時刻・学習終了時刻の裏付けには NAS 側の保存履歴が必要です。

発走前入力の区分は `input_evidence_grade` に記録します。`schema_version: 2` の比較設定では、省略した区分を C とします。準備コマンドは入力設定のバージョンにかかわらず、未指定を C としてバージョン 2 のフィクスチャを生成します。直接実行する従来の `schema_version: 1` 設定では、互換性のため未指定を A とし、従来の時刻と SHA の検査を適用します。

| 区分 | 発走前入力の証跡 | 取り扱い |
| --- | --- | --- |
| A | 発走前の取得を確認済み | 正式検証・参考検証・計算監査 |
| B | 内部記録あり・独立した証跡不足 | 参考検証・計算監査 |
| C | 取得時点不明 | 計算監査のみ |
| D | 発走後の情報が混入 | 原因調査のみ |

既定の `"evaluation_mode": "formal"` は A のみを集計します。`"evaluation_mode": "reference"` は A と B を対象にし、B にも内部記録による発走前の取得時刻と SHA の検査を適用します。参考検証の学習入力は A に限定し、候補選定は無効です。参考検証の成果物は `--output` 配下の `reference/` に保存し、データ行とマニフェストに検証モードを記録します。`races` では各レースの入力区分を確認できます。同じ出力先を使う場合は空の出力先に正式検証を出力してから参考検証を実行してください。計算監査と原因調査に使う区分はフィクスチャのメタデータに記録します。

## フィクスチャ準備

上記形式の比較設定から、入力ファイルを複製し、SHA-256 を付けたフィクスチャを作成します。出力ディレクトリには新規パスを指定してください。

```sh
python -m tools.prepare_ab_comparison --config /path/to/run.json --output /path/to/new-fixture
python -m tools.compare_ab_models --config /path/to/new-fixture/run.json --output /path/to/report
```

設定の `results` に既存形式の確定結果 Excel（`.xlsx`）を指定する場合は、`--result-evidence /path/to/evidence.json` を追加します。この JSON にはレース ID と下記の証跡フィールドを配列で指定します。着順と払戻は Excel から取り込みます。比較モデル設定、固定候補マニフェスト、実購入台帳は元の参照先を使います。

## 確定結果と集計

`results.json` は別ファイルの配列です。着順は1着から順に、払戻金は各100円あたりの確定金額を指定します。複勝は頭数に対応する全的中馬の金額を収録します。3連複の組番は馬番昇順のハイフン区切りです。

```json
[
  {
    "race_id": "202605050101",
    "evidence_grade": "A",
    "finalized_at": "2026-07-01T12:20:00+09:00",
    "finish_top3": [2, 1, 3],
    "payouts": {
      "単勝": {"2": 280},
      "複勝": {},
      "3連複": {"1-2-3": 1950}
    }
  }
]
```

| グレード | 結果の証跡と指定項目 | 利用範囲 |
| --- | --- | --- |
| A | 正確な確定時刻を `finalized_at` にタイムゾーン付きで指定 | 事後評価・締切判定 |
| B | `race_date`、信頼できる保存履歴の参照先 `evidence_source`、利用可能日の上限 `available_by_date`（JST） | 事後評価・締切判定 |
| C | `race_date`、JRA公式確定結果の参照先 `evidence_source`、公式結果の転記 `jra_official_result` | 事後評価のみ |
| D | 出典や内容を確認できない | 利用不可 |

B/C の `race_date` と B の `available_by_date` は `YYYY-MM-DD` です。B の上限日は、その日までに対象の着順・払戻が利用できたことを保存履歴で確認して指定します。C の `jra_official_result` には `race_id`、`race_date`、`finish_top3`、`payouts` を入れます。実際の JRA 公式資料との一致確認は入力準備工程で行い、後から確認できる参照先を記録してください。ツールでの C の照合は、提供された公式結果の転記データとの比較です。比較項目はレース ID・開催日・着順と、利用対象の各券種の払戻です。B の保存履歴も入力準備工程で確認します。

従来形式の `finalized_at` 付きデータは A として読み込みます。締切日を含む学習・検証期間では、A の確定時刻を JST に直して締切日までかを判定します。B は利用可能日の上限が締切日より前のときに限って学習と候補選定に使います。フィクスチャと比較結果のマニフェストにはレース別の `grade`、`finalized_at`、`race_date`、`available_by_date`、証跡の参照先を記録し、不明な時刻は `null` で表します。

欠落した券種はキーを省略します。買い目が外れたことを確定できる場合だけ払戻にゼロを計上します。同着・返還など単一の確定上位3頭と対応する払戻で表現できないレースは、着順・払戻集計の対象外とし、結果の欠落として明記します。勝率と回収率の分母、購入予定額と精算対象の投資額を個別に記録します。

- `comparison` と `breakdown` は CSV/JSON で、集計期間、月、競馬場、距離、クラス、A の1位馬の発走前人気帯を使います。各方式自身の人気帯は `races` で確認できます。TOP5の3着以内捕捉率は、確定3着以内の延べ頭数に対する捕捉頭数の割合です。最大連敗は払戻ゼロの精算済み購入レースの連続数です。
- 馬券は同じ頭数の3連複ボックスと同じ単価で比較します。`filtered` は既存の新馬・未勝利除外および第1判定を全4方式に適用し、全方式が購入候補となったレースを採用します。各方式の判定は `races` で追跡できます。高額払戻は各方式の上位と、全方式の上位レースの和集合を取り除いた同一母集団で集計します。
- `manifest.json` はコード、方式別重み、固定条件、期間、候補選定、欠損件数、サンプル数、成果物 SHA を記録します。除外理由は `exclusions`、探索したグループの結果は `optimizer_C.csv` / `optimizer_D.csv` に出力します。前向き照合は既評価期間として別集計します。

## 修正前 main と D 項目

`diagnostics` は同一の発走前入力・固定重みで、特徴量セル、スコア、順位、馬券指標を比較します。修正前 main の特徴量関数は PR #31 の親コミットから読み込み、差があれば成果物を保存したうえで終了コード2を返します。D-01 はキャッシュを外した main を基準にし、累積差は前の固定コミットと比較します。D-02・03・04・05・09 の単独差は D-01 の共通基準に個別パッチだけを適用します。D-12 は特徴量の変更を含まないため、当該コミットの重み実体と修正前後の設定 SHA を照合します。

D-04 の出走数 `ta_n` は競走中止を出走に数え、除外・取消を除きます。中止の着順は欠損として扱います。D-09 の `win_rate` は有効な着順がある走だけを分母とし、該当がゼロなら欠損です。例えば1着・2着・競走中止の3走では、出走数は3、勝率は1/2です。両指標の比較前後の値は馬番ごとに出力します。

## 2026-08-09 の単日比較

設定に `"evaluation_date": "2026-08-09"` を追加すると、既定の
`weight_mode=ab_only` で、その日の発走前入力と確定結果から A・B のみを計算します。
単日比較の結果からは候補選定を行いません。

C・D も計算する場合は、次のいずれかを指定します。

- `"weight_mode": "optimize"` を指定し、評価日より前の学習スナップショットと学習締切までの利用可能性が確認できる結果を用意します。
- `"weight_mode": "fixed"` と `"candidate_manifest": "previous/manifest.json"` を指定し、
  以前の実行で出力したマニフェストと C・D の重みファイルを用意します。
  学習終了日が評価開始日より前で、学習レース ID が評価レースと重複せず、
  C・D の学習レースと期間が一致し、重みの SHA が一致する場合に読み込みます。
  該当マニフェストの基準名が `github` 以外の場合は `candidate_manifest_baseline` を指定します。

## 方式別の購入対象と実運用成績

固定3連複BOXの比較には、全対象レースの `all_*`、有効な全方式が購入候補の
共通対象 `filtered_*`、各方式自身が購入候補の `own_filtered_*` が含まれます。

既存購入条件による実運用成績は `operational_comparison.csv` と
`operational_comparison.json` に出力します。設定の任意項目
`"operational_results": "actual_purchases.json"` が、購入当時の判定と実際の購入・精算を
記録した台帳を指します。1行は基準・方式・レースごとに集約済みの実購入です。
台帳の `baseline`、`method`、`race_id` を比較対象と照合し、
当時の `purchase_decision` が `購入候補` の記録を使います。精算未取得は
`"payout_yen": null` で指定します。

```json
[
  {
    "baseline": "github",
    "method": "A",
    "race_id": "202605050101",
    "purchase_decision": "購入候補",
    "investment_yen": 400,
    "payout_yen": 725
  }
]
```

台帳に実績がない方式・期間の実運用成績は集計不能として出力します。
精算済み30レースは候補選定の最低条件であり、本番採用の十分条件ではありません。
SHA-256 はファイルの内容を固定し、発走前の取得時刻は元の保存記録で確認します。
整形後の共通入力が一致しても、当日の生入力・実行環境を含む現行モデルの完全再現には追加の照合が必要です。
