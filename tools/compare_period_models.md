`python -m tools.compare_period_models --inventory /path/to/audit-days.json --output /path/to/run`

PR #31 の履歴がある Git チェックアウトで実行します。GitHub の現行本番モデルと既存 A/B 比較の第1購入判定、5頭の3連複ボックス、1点100円を全方式に使用します。収益は仮想馬券で、実購入記録は `not_provided` です。期間は学習・探索 2025-06-14〜2026-06-30、検証 2026-07-01〜2026-10-23、後期照合 2026-10-24〜2026-11-23 です。学習・探索期間も固定条件で集計し、再学習は行いません。後期照合期間は使用済みの期間です。

## 開催日目録

期間監査の開催日一覧を `days` に指定します。下の例のハッシュはプレースホルダーです。パスは目録を基準に解決します。開催日と原本ワークブックの対応は監査目録から設定し、レースIDは各日の `今走レース情報` シートから取得します。原本未提供の日も `date` だけで目録に含められます。レースIDが分かる場合は `races` に置くと欠損の内訳に残ります。

```json
{
  "schema_version": 1,
  "results_workbook": "data/input/確定結果.xlsx",
  "results_workbook_sha256": "<確定結果ExcelのSHA-256>",
  "days": [
    {
      "date": "2026-08-09",
      "workbook": "data/input/馬の競走成績_20260809.xlsx",
      "workbook_sha256": "<開催日原本のSHA-256>",
      "races": {
        "202605050101": {
          "input": {
            "input_evidence_grade": "A",
            "input_evidence_source": "発走前の独立した保存記録への参照",
            "start_at": "2026-08-09T12:00:00+09:00",
            "observed_at": "2026-08-09T11:55:00+09:00",
            "popularity": {"1": 1, "2": 2},
            "popularity_observed_at": "2026-08-09T11:54:00+09:00"
          },
          "result": {
            "evidence_grade": "B",
            "evidence_source": "確定結果保存記録への参照",
            "available_by_date": "2026-08-09"
          }
        }
      }
    }
  ]
}
```

- 日別結果ファイルは各日の `results_workbook` と `results_workbook_sha256` で指定できます。結果Excelはリポジトリの確定結果と同じ着順・馬番、券種・組番・払戻金の列を使用します。着順と払戻を別々に読み、不足や出走表と照合できないデータを欠損として数えます。
- レースごとの入力証跡は任意です。A は発走前取得を裏付ける独立した証跡、B は発走前取得の内部記録を参照します。どちらも証跡の参照先と発走前の取得時刻が必要です。原本に出走表があり取得時刻や証跡を確認できない場合は C、発走時刻以降の取得が確認できる場合や出走表がない場合は D です。人気は発走前の保存値を指定します。省略または不足時は既存の購入判定に従って保留になります。発走前のレースレベル・基準タイム・オッズ・DL を使う場合は既存 A/B 入力と同じ各項目、SHA、観測時刻を `input` に指定します。 [既存 A/B 入力仕様](compare_ab_models.md)
- 結果は A には発走後の `finalized_at`、B には `available_by_date` と証跡の参照が必要です。C には JRA 公式確定結果への参照と、レース ID・開催日・確定着順・使用する払戻が一致する `jra_official_result` が必要です。照合資料のない結果は `unverified` として保持し、着順が欠損・不整合の場合は D です。供給された公式結果との不一致はエラーになります。着順は照合できて払戻だけが欠損する場合も、着順の指標と結果証跡を保持します。
- 日ごとの入力証跡と結果証跡は独立に集計し、日内の最も低い区分と全区分の内訳を表示します。同日に証跡が混在するため、収益評価の対象はレース単位で決定します。結果 A/B/C と組み合わせた入力 A は `formal`、入力 B は `reference` に入れます。入力 C と未照合結果は計算監査に使用します。入力 D は予想と収益比較から除外し、結果 D は収益評価から除外します。日付や払戻の推測、データの外部取得は行いません。

## 出力と再開

- 特徴量処理中は開催日ごとの件数を順次表示し、スコア処理前に `coverage.json` に全体・期間別・開催日別の件数を保存します。正式・参考の収益検証可能件数は、確定着順・3連複払戻を照合でき、5頭以上のレース数です。実際の仮想購入件数は購入判定の結果によります。160日との差は目録件数と照合できます。
- `features/YYYY-MM-DD/M00.json.gz` などに全特徴量を保存します。Python では `tools.compare_period_models.read_frame(path)` で読み込めます。スコアと順位は `scores/YYYY-MM-DD/` に分け、各開催日のマニフェストにコード・入力・出力のハッシュを記録します。台帳に相当する実購入データは読み込みません。
- `comparison.csv` と `comparison.json` に全期間・期間別の指標を出力します。仮想馬券の `all` は各方式で比較可能な共通の全レース、`filtered` は全方式が購入候補とした共通集合、`own_filtered` は方式ごとの購入候補です。精算には確定着順と当該券種の払戻が必要です。
- M00 は既存 A/B の A、M04 は既存の corrected と同じ生成経路です。他の方式は M00 の horses 補完条件を維持します。`comparison.csv` と `comparison.json` には、M00・M04 と同じ期間・コホートで `legacy_no_cache` と `corrected_with_cache` を `diagnostic_only` として併記します。診断方式は9方式の共通購入集合を決める判定には含めません。`cache_diagnostics.csv` では補完の有無による特徴量・順位・購入判定などの差をレースごとに確認できます。D-12 の SHA 整合は `feature_configuration.json` に記録します。
- 再開は同じコミット・目録・実行環境・出力先で同じコマンドを実行します。開催日ごとの確定済みファイルを再利用し、集計は保存済みの開催日結果から再構成します。入力を更新した場合は SHA を更新した目録と別の出力先を指定します。
