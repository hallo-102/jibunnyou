# レース購入適性判定：第1判定・第2判定・評価困難診断

本番モデルの重み・順位・買い目は変更しません。Excelを読み込むと、全競馬場・全レースを対象に次の3つを**分けて**計算・固定保存します。

1. **第1判定**：人気5位以内かつ本番AI能力順位6位以下の馬を抽出し、購入適性を判定。
2. **評価困難診断**：能力評価に必要な情報が不足、または他馬と比較しにくい馬を6分類で検出。
3. **第2判定（研究用）**：過去走のレースレベル・時計差などの特徴量と、将来係数を確定したときの独立順位比較。初期状態では係数・閾値未確定です。

旧版の「独立順位との差が3位以上」「時計50%＋相手クラス25%＋距離25%」は廃止しました。クラスを相手ratingの代理として埋めません。

## 操作

1. `run.bat` で起動します。親フォルダの `.venv\Scripts\python.exe` を優先し、なければ `py -3` を使います。
2. **発走前に**「Excel読込 → 第1・第2判定を固定保存」を押し、予想Excelを選びます。
   対象日と同じ `OZZU_YYYYMMDD.csv` をNASから自動読込します。CSVの選択操作は不要です。
3. 一覧に、第1購入適性・不一致数・未判定数・不一致馬番・評価困難馬数・第2判定の状態を表示します。競馬場・第1購入適性で絞り込めます。
4. 行を選ぶと、馬番・馬名・人気・AI順位・順位差・判定理由・取得時刻・過去走の数値と出典を箇条書き表示します。第2の未確定項目も明示します。
5. 読込時に判定・根拠を `data/evaluations.jsonl` へ追記固定します。同じExcel・同じマスター・同じ設定では再読込しても上書きしません。
6. レース後は行をダブルクリックし、「レース後結果」で保存IDを選択して確定1〜3着を入力します。購入券は任意です。
7. 「結果検証」で、第1と第2を別々に、TOP5捕捉率、レース数、仮想投資・利益・回収率を確認します。

Python 3.11以上・tkinter・openpyxlが必要です。マスター読込には十数秒かかる場合があります。事前判定タブや手動の不一致数入力はありません。

### 判定一覧のExcel出力

画面上部の「判定一覧をExcel出力」を押して、保存先とファイル名を選択します。

- **判定一覧**：現在表示しているレースと、第1・第2の判定、不一致数、固定保存時刻など。
- **馬別詳細**：対象レースの全馬について、人気・AI順位・オッズ・判定理由・評価困難フラグ・取得時刻・出典。
- **出力情報**：絞り込み条件、保存ID、原本SHA256、方式バージョン、人気CSVの取得元など。

競馬場・購入適性の絞り込みを反映します。全レースを出力する場合は両方を「すべて」にします。未読込・表示0件の間はボタンを無効にします。固定保存した値を再計算せず出力し、元Excelや判定保存データは変更しません。読込原本への上書きは防止しています。

## 第1判定：定義と欠損の扱い

馬ごとに、**人気順位 <= 5 AND 本番AI能力順位 >= 6** を評価します。

| 人気／本番AI | 判定 |
|---|---|
| 2番人気／AI6位 | 不一致 |
| 5番人気／AI11位 | 不一致 |
| 3番人気／AI4位 | 一致（不一致なし） |
| 7番人気／AI2位 | 不一致対象外 |

- 人気は指定NASの対象日オッズCSVを使います。AI順位はExcelの「予想順位／本番AI順位」などの**馬別の確定順位列**を使い、本番順位は変更しません。人気からAI順位を作ったり、TOP5から欠損順位を補ったりしません。
- 表示する順位差は `AI順位 − 人気順位`。不一致の条件は順位差そのものではなく、上記2条件です。
- 人気・AI順位の欠損、不正値、頭数や馬番の整合性不足は保留です。不明な馬を不一致0頭として数えません。
- 人気はCSVの取得時刻列があれば使用し、なければ**NAS CSVの読取時刻**を観測時刻として保存します。AIはExcelの「AI順位取得時刻／AI確定時刻」があれば使用し、なければExcelの読取時刻です。ファイル更新日時を元の取得時刻の証拠としては使いません。
- 各値の取得・観測時刻が評価時刻以前かつ発走前であることを確認します。過去開催のファイルを後日読んでも、発走前に取得したと推定しません。条件式だけに当てはまる馬は「参考条件該当」として示し、確定不一致数と分けます。
- **全頭の第1判定が確定し、不一致0〜1頭なら購入候補、2頭以上なら見送り候補**。必要データ不足や未判定があれば判定保留を優先します。
- 過去走不足などの評価困難フラグは別の診断です。人気・AIの2条件による不一致数と混ぜません。第1で購入候補でも、独立能力を十分に評価できたという意味ではありません。

## 人気オッズCSVの自動読込

- NASフォルダ：`\\192.168.1.92\docker\keiba_yosou_2026_nas\data\ozzu_csv`。変更する場合はアプリ内の `odds_source.json` の `directory` を設定します。
- 開催日が2026年11月22日なら `OZZU_20261122.csv` を選びます。別日の最新CSVで代用しません。
- 必須列は `date,racecourse,race,name,bet_type,combination,odds`。`bet_type=単勝` だけを使い、日付・競馬場・R・馬番・馬名を照合します。
- 人気順位列がない場合、単勝オッズ昇順の**推定人気**を使います。表示オッズが同じ場合、公式人気の順番までは分からないため順位区間で保持します。
- 同オッズが5番人気の境界をまたぎ、AI6位以下のときは判定保留。区間全体が5位以内、または6位以下なら2条件の結論を確定できます。同オッズを馬番順で順位付けしません。
- CSVに明示的な `popularity_rank / pop / 人気順位 / 人気` 列がある場合はその順位を検査して使用します。
- 対象日のCSVがない、NASへ接続できない、頭数不足、オッズ欠損、重複矛盾、馬名不一致は保留です。Excelの人気に暗黙フォールバックしません。
- CSVに明記された今走馬名・馬番により、Excelで未取得の出走馬を補える場合があります。ただしAI順位は作らないため、AI順位がない馬は保留です。
- 読み込んだCSVのバイト列を `data/odds_snapshots/OZZU_日付_SHA256.csv` へ変更不可の別ファイルとして保存し、取得時刻・原本パス・SHA256・CSV行・オッズ・算出方法を判定と一緒に保持します。NASのファイルは変更しません。
- 同じCSVを読み直しただけなら同じ判定を再利用します。CSVの内容が更新された場合は別の入力指紋で保存し、過去保存は上書きしません。

## 評価困難な馬の6分類

| 分類 | 診断例と表示する根拠 |
|---|---|
| ①過去走不足 | 確認できた経験が0〜2走。観測できた過去走数を表示 |
| ②条件比較困難 | 同じ芝ダート・近似距離の経験なし、今走条件不明。経験数と今走コースを表示 |
| ③時計比較困難 | 同競馬場・同芝ダート・同距離の基準時計や、馬場・ペース差補正情報が不足 |
| ④相手比較困難 | 発走前rating・レースレベル・相手次走情報が不足。取得件数と確認率を表示 |
| ⑤内容評価困難 | 位置取り・ラップが不足、不利の記載、原本の列と値の対応を確認できない |
| ⑥現在能力不確実 | 長期休養、成長期、直近走不明。休養日数・年齢を表示 |

診断用の近似距離は±200mまたは±10%、長期休養は180日を初期値としています。2〜3歳は成長期として能力変化量が未確認である旨を表示し、「成長が大きかった」と断定しません。判明している過去走数であり、完全な生涯出走数を取得したという意味ではありません。

原本にない馬名・今走馬番は生成しません。原本の今走表にない障害馬は、過去走から馬名を取得できても今走馬番・人気・AI順位は不明のままです。新馬の馬名等が原本に存在しなければ不足頭数を示します。

## 第2判定：特徴量と時点管理

### 対象とレベル補正着差

- 全競馬場・全レース・全馬について、予想対象日より前の**直近365日・最大5走**を新しい順に選びます。欠損のある最近走を飛ばして都合のよい古い走りへ置き換えません。
- 過去走能力値 = **レースレベル − β × (自馬走破時計 − 勝ち馬走破時計)**。着差欄の馬身を秒へ推測換算しません。
- レースレベルは、①自馬を除く全相手の発走前`pre_rating`平均、②不足する場合は`race_levels.race_level_score`。最新ratingやpost_rating、クラス点数で代用しません。
- β候補は **0, 2, 5, 10, 15, 20, 30**。選択前は全候補の特徴量を並記し、勝手にβを決めません。
- 各βで近3走平均と**半減期180日**の減衰加重平均を計算します。近3走平均は3走揃う場合のみ算出。加重平均も選ばれた走に欠損があれば未算出です。未知の着差・レベルを0にしません。

### ローカルマスター

`data/master/race_levels.xlsx` の `races / horses / entries / race_levels / README` を読みます。

- README記載の作成日時を利用可能時点として保持し、SHA256と参照行も保存します。作成日時が不明・予想時刻より後の版は使用しません。
- レースIDだけでなく、過去走の日付・芝ダート・距離も照合します。IDの衝突や開催日の不一致を推測補正しません。
- `entries.pre_rating` は発走前rating列として扱い、自馬を名前・馬IDで除外します。相手全員分がない場合は平均値を確定せず、レースレベルへフォールバックします。
- 作成日時より未来の日付のレースを「その版で既知だった」と扱いません。マスター更新・設定変更時は入力指紋も変えて、過去保存と別記録にします。

### 時計・ラップ・相手次走

- 基準時計差 = 自馬時計 − 同競馬場・同芝ダート・同距離の基準時計。小さいほど高評価です。
- 現在は、利用時点を確認できるマスター内の過去の同条件勝ち時計を3レース以上集めた中央値を、時点再構成の基準時計として使用します。作成時刻、データ締切、元版の利用可能日時、件数、参照レースID、SHA256を保存します。
- 既存の `場所_馬場_タイム.xlsx` は作成時点を確認できないため、この判定には無条件で流用しません。同日馬場補正は第2段階で、現在は未実装です。
- 200m刻みを確認できるラップでは、前後半3F・4F、最速1Fと全出現位置、最速連続3Fと全開始位置を算出します。1700m等で刻みが確認できない場合は区間指標を出しません。**レース全体のラップは各馬固有の末脚として扱いません。**
- 相手の最初の次走から着順／頭数を数値化し、判明分の平均と確認できた相手の割合を別々に記録します。予想締切後の結果は使わず、未確認率を0の成績として埋めません。最初の次走が未取得でもその次の走りへ飛びません。

### 未確定係数を適用しない仕組み

`assessment_policy.json` の β・重み・順位差閾値は初期値`null`です。この間は、統合スコア・独立順位・第2不一致数を確定しません。状態は「係数・閾値未確定」です。

将来適用するには、過去の選択期間、選択根拠、事前固定日時を記録したうえで設定します。選択期間は予想日より前、固定日時は選択期間終了後かつ予想締切以前である必要があります。アプリが今回の結果を見てβ・重み・閾値を最適化する処理はありません。

対応する統合特徴量は近3走能力平均、減衰能力平均、時計優位（基準時計差の符号反転）、相手次走強度（1−着順／頭数）です。重みが確定した場合のみレース内で標準化して統合します。欠損馬・同点馬は順位区間で扱い、確定できない差は保留。順位差の方向は**本番AI順位−独立順位**です。

第2で「2頭以上なら見送り」が有効かは未検証です。購入可否へは混ぜず、比較可能になった後も「不一致0〜1頭／2頭以上の研究群」として第1から独立して記録・検証します。

## 固定保存と結果検証

- 原本・マスター・設定の入力指紋、両ロジック、全馬の値・理由・取得時刻、評価困難フラグ、根拠行、TOP5、事前の仮想買い目を固定保存します。
- 読込時の保存が発走前の場合だけ前向き検証に使用します。事後保存を事前保存へ変更しません。旧v1/v2の保存や手動記録も書き換えず、方式バージョンごとに分けます。
- 結果は`evaluation_id`へ結合して `data/results.jsonl` に追記。重複結果・購入券の件数でレース数を増やしません。矛盾する着順・複数原本の事前保存は都合のよい方を選ばず除外します。
- TOP5捕捉率は「保存TOP5に含まれた確定1〜3着の頭数 ÷（比較可能レース数×3）」。本番・独立それぞれの分母を表示し、未確定TOP5を捕捉0で埋めません。
- 第1は全体・購入候補・見送り候補・保留。第2は全体・不一致0〜1頭の研究群・2頭以上の研究群・未算出／保留を別集計します。

### 仮想利益・回収率

- 「回収率重視_買い目候補」に明記された3連複・馬連・ワイドの組み合わせと金額を、**事前の仮想買い目**として保存します。買い目のないレースは未知であり、投資0とみなしません。
- 金額を点数で等分でき、各点が100円単位のときだけ扱います。券種別合計金額を各点の金額として二重計上しません。
- 結果入力の仮想払戻欄は、1行 `券種,組み合わせ,100円あたり確定払戻額`。例は `馬連,3-5,2500`。実購入券の払戻総額とは別欄です。
- 的中券は `100円払戻額×購入単位数`、不的中券は確定着順から0円と確認できます。的中券の払戻が未知・矛盾なら収支は未計算です。
- 投資・払戻の不足が1レースでも残る群は、群全体の利益・回収率を未計算にします。明細不足を0で補いません。原本で買い目が4レースにしかなければ、残りのレースを含む群全体の仮想利益は計算できません。
- 同じ保存買い目を第1・第2の各群に振り分けるため、比較途中で買い目や金額を作り替えません。実際に購入したことや利益改善が実証されたことを意味しません。

CSVは `race_id,finish_top3,evaluation_id` を使用できます。保存IDを省略できるのは同じrace_idの固定保存が1件のみの場合です。仮想払戻CSVは `race_id,evaluation_id,ticket_type,combination,payout_per_100`。取込前に全行を検査します。

## テストと旧資料

### 毎朝8:10の自動追記

`daily_judgement.py` はGUIを起動せず、同じ判定式・人気CSV・過去走マスター・固定保存を使用します。Codexの自動化「当日予想Excelへ判定一覧を追加」を毎日8:10（Windows設定：日本時間）で登録しています。実行にはこのPC、Codex、およびNAS接続が利用可能である必要があります。競馬の判定アプリを開く必要はありません。

- 入力：`\\192.168.1.92\docker\keiba_yosou_2026_nas\data\output\馬の競走成績_with_feat_YYYYMMDD.xlsx`。例：2026年11月22日は `20261122`。ファイル名の日付は年月日順です。
- 当日分がない日は正常終了してスキップします。NAS接続不可・Excel使用中などの失敗はログへ記録します。別日のファイルへ切り替えません。
- 同じExcelに「判定一覧」「判定馬別詳細」「判定出力情報」の3シートを末尾追加します。既存の予想順位・シートXML・数式の計算済み値・画像などは保持します。
- 人気CSVが不足している場合も、既定の欠損処理に従い「判定保留」を記録します。事後の実行を発走前保存にはしません。第2の未確定係数は確定させません。
- 追記前の原本：`data/daily_judgement/originals/<原本SHA256>/`。アプリの判定原本は従来どおり `data/evaluations.jsonl` に固定保存します。
- 当日実行記録：`data/daily_judgement/YYYYMMDD.json`。ログ：`data/daily_judgement/logs/YYYYMMDD.jsonl`。
- 追記済みファイルの同じ内容は再実行しても変更しません。原本が作り直された場合は別の原本として保存して処理します。既存の判定シートと実行記録が一致しない場合は停止し、自動上書きしません。
- 処理中の更新を検知した場合は置換を中止します。書込みは同じNASフォルダ内の一時ファイルから置換するため、Excelを使用中の場合は閉じてから再実行してください。

手動実行はこのフォルダをPowerShellで開いて行います。

```powershell
$env:PYTHONIOENCODING = 'utf-8' # 日本語ログをUTF-8で出力します。
& '..\.venv\Scripts\python.exe' '.\daily_judgement.py' # 日本時間の当日分を追記します。
```

強制終了後に `.lock` ファイルが残った場合は、同時実行中でないことと当日ログを確認してから該当ロックだけを削除し、再実行します。予想Excelが追記後に編集されて実行記録と異なる場合は、バックアップを使った復元・確認が必要です。

`python -m unittest discover -s tests -v` で、第1の4例・0/1/2頭境界、欠損・取得時刻、診断との分離、365日/5走・半減期、相手rating優先・自馬除外、未来データ除外、係数未確定、仮想払戻・重複、GUI、固定保存を検証します。

`docs/illustrated_manual/` は旧画面の資料です。現在の定義と操作は本READMEが優先です。
