# 独立レース購入適性判定アプリ (race_purchase_filter)

2026-11-21(土)・22(日)から「予想しにくいレースは見送ったほうがよいか」を前向き検証するための独立アプリです。
本番予想モデル・production_model.json・予想順位・買い目は変更しません。本アプリは本番予想モデルとは独立しています。

## 起動方法

- Windows 11 / Python 3.11 を想定しています。
- `run.bat` をダブルクリックするか、以下を実行してください。

```
pip install -r requirements.txt
python app.py
```

- 依存は標準ライブラリ + tkinter（GUI）です。xlsx読取のみ `openpyxl` を任意依存とします。未インストール時はその旨を表示し、手動入力で継続できます。
- `requirements.txt` には openpyxl のみ記載しています。

## 画面（tkinter 4タブ）

1. **事前判定入力**：評価不一致数などの事前情報を入力し、スナップショットを保存します。
2. **レース一覧**：読込んだ xlsx の開催日/場/R/race_id/出走馬一覧を表示します。
3. **レース後結果**：確定着順・購入券・払戻を入力します。結果CSV／チケットCSVの取込にも対応します（`sample_results.csv` / `sample_tickets.csv` の列仕様参照）。
4. **方式比較**：A/B/C方式の集計を表示します。

データはアプリフォルダ配下の `data/`（`snapshots.jsonl` / `results.jsonl`）に保存され、再起動後に復元されます。

## xlsx 入力

- 既存『馬の競走成績_with_feat_YYYYMMDD.xlsx』を読み取り、開催日/場/R/race_id/出走馬一覧を表示します。
- 列名は候補名リストで柔軟に探します：開催日・日付・date／競馬場・場・place／R・レース番号・race_no／race_id・レースID／馬番／馬名／レース名・クラス等。
- 見つからない項目は推測で埋めず「不明」とします。
- ファイルの SHA256 を計算して保持し、スナップショットに保存します。

## 最重要：評価不一致馬の数について

**評価不一致馬の数は手動入力のみです。算出式未確定のため手動入力としてください。**

- 原本で算出する列・算出式が未確認のため、自動計算は実装していません。
- 「本番vsシャドーTOP5差」等で代用していません。評価不一致とモデル間TOP5差は別物です。
- 画面にも同じ注意書きを表示しています。

## 暫定判定（検証用）

この判定は検証用の暫定判定であり、自動購入可否ではありません。

| 評価不一致数（手動入力） | 判定 |
|---|---|
| 0〜1頭 | 購入候補 |
| 2頭以上 | 見送り候補 |
| 未入力／不明 | 判定保留 |

## 比較困難項目と C方式

- 相手関係比較困難・時計比較困難は別項目として入力できます（該当頭数、該当馬番号、根拠メモ、データ未取得フラグ）。
- **C方式の閾値は未確定**のため、Cは初期状態では「判断保留・未算出」とし、ログ保存だけ行います。
- **Cの回収率・利益は計算しません。**

## 事前判定スナップショット

予想時点の以下を JSONL 追記専用で保存します：記録時刻、元データファイル名、SHA256、モデル世代（手動入力、例 20260730 / 20260817）、評価不一致数、該当馬番号、比較困難2項目の内容、A/B/C判定、条件バージョン文字列。

- 一度保存したスナップショットは変更・削除できません（更新・削除APIを持たない設計）。
- 同一 race_id + 同一 SHA256 の二重保存はエラーになります。
- 結果データでスナップショットを上書きしません。結果は別ファイル `results.jsonl` へ追記します。

## レース後入力と的中判定

- 入力：確定1〜3着馬番、TOP5捕捉数（確定1〜3着のうち予想TOP5に含まれる頭数。予想TOP5馬番を事前スナップショット側または結果入力で保持し、未入力なら「未計算」）、実際に購入した券種/組み合わせ/各点金額/払戻額。
- 的中判定は購入券の組み合わせと確定着順の照合で計算します。**結果シートの「的中〇」欄は使いません。**
- 対応券種：単勝（1着と一致）、複勝（1〜3着に含む）、枠連・馬連・ワイド（順序なし2頭。ワイドは1〜3着の2頭の組合せ）、馬単（順序あり2頭＝1着・2着）、3連複（順序なし3頭＝1〜3着の集合）、3連単（順序あり3頭）。
- 組み合わせ表記は `"3-5"` / `"3-5-7"` 形式です。照合できない券種・形式は「不明/未計算」とし、推測しません。

## 方式比較集計

**前提：同一原本・同一券種・同一金額であること。** この前提を画面と本READMEの両方に明記しています。

- **A**：現行条件だけで購入＝結果とチケットが記録された全レース
- **B**：Aのうち評価不一致0〜1頭のレースのみ（2頭以上と不明は除外し、除外件数を表示）
- **C**：閾値未確定のため常に「未算出」と表示

各方式で購入レース数、投資額、払戻額、損益、回収率（投資0なら未計算）、TOP5捕捉率（捕捉数が記録されたレースのみで計算し分母を表示）を出します。
未確認データは0に補完せず「不明/未計算」と表示します。

## 設定・条件バージョン

- 新馬・未勝利戦を購入対象外とする設定があります（レース名/クラス文字列に「新馬」「未勝利」を含む場合に対象外フラグ。判定はしますが比較集計の対象外として区別表示します）。
- 条件バージョンをスナップショットに保存し、過去開催の比較は当時の条件のまま復元します。**条件変更を遡及適用しません。**

## 参考値について

9/5の17レース観測（不一致>=2: 5RでTOP5捕捉46.7%、0〜1: 12Rで88.9%）は、**参考値（原本一致のレースIDと算出定義が未確認のため再現済み実績ではない）**としてのみ記載します。アプリ画面には実績として表示しません。

## データ品質に関する注意

- 2026-10-03のpre JSONは生成時刻が遅く前向き検証に含めません。
- 世代（20260730 / 20260817）は分けて管理してください。
- 評価不一致とモデル間TOP5差は別物です。
- JSONの `purchases=0` / `payout=null` は回収率計算に使えません（不明として扱い、0補完しません）。

## テスト

```
python -m unittest discover -s tests -v
```

受入基準との対応：不一致0/1→購入候補・2→見送り候補・空欄→保留、スナップショットの変更不可と二重保存エラー、馬連・3連複・3連単・単勝等の的中照合、A/B集計の手計算一致とC未算出、不明データを0補完しないこと（回収率が未計算になるケース）をテストで確認します。
